# A public source directory for POTIFY

A visitor who finds POTIFY through a film can follow the recording, the book and the game. A developer needs a different kind of link: the exact revision that supports each project's claims. This directory gives each a consistent way to inspect that evidence without requiring a wallet or an account in any POTIFY service.

## Evidence model

One entry identifies the repository, branch, commit, Git tree, release scope and project goal. The commit identifies history. The tree identifies the files. Each project owns its README, technical description, build log and commercial experiment. A game build, a field guide, a reference implementation and a specification carry different labels.

## Boundaries

Public code is separate from private operating records. Account and wallet integrations can be reviewed without exposing members, case files, transactions or merchant records. No purchase, token holding or claim is required to use the directory. GLP maintains separate commercial ownership and operations.

## Maintenance

A maintainer verifies the source change, tests and project scope, then updates the pinned commit and tree in the same review as the changed description. The verifier checks the local catalog or reconciles it against public GitHub branches. A changed branch is a signal to review the intervening work. Readers can always inspect the pinned commit.
